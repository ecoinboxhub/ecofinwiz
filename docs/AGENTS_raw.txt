STYLE:Normal|FINWIZE AI ENGINEERING CONSTITUTION
STYLE:Normal|Purpose
STYLE:Normal|This document defines the engineering principles, implementation priorities, architectural constraints, and decision-making framework for every AI coding agent contributing to the FinWize project.
STYLE:Normal|This is not merely a software project. It is an AI-first financial inclusion platform designed to improve financial literacy, resilience, and entrepreneurship across underserved African communities.
STYLE:Normal|Every implementation must advance this mission.
STYLE:Normal|
STYLE:Normal|1. Mission
STYLE:Normal|Build Africa's most accessible conversational AI financial assistant that helps individuals and small businesses make better financial decisions through natural voice and chat interactions.
STYLE:Normal|The project prioritizes:
STYLE:Normal|Financial inclusion
STYLE:Normal|Accessibility
STYLE:Normal|Financial literacy
STYLE:Normal|SME empowerment
STYLE:Normal|Low-bandwidth usability
STYLE:Normal|Trustworthy AI
STYLE:Normal|Measurable social impact
STYLE:Normal|Every engineering decision should reinforce these objectives.
STYLE:Normal|
STYLE:Normal|2. Core Product Definition
STYLE:Normal|FinWize is NOT a collection of disconnected fintech tools.
STYLE:Normal|FinWize is a single conversational AI platform.
STYLE:Normal|The conversational assistants are the product.
STYLE:Normal|Personal Finance Assistant
STYLE:Normal|Kemi
STYLE:Normal|Responsibilities:
STYLE:Normal|Budget coaching
STYLE:Normal|Expense tracking
STYLE:Normal|Savings guidance
STYLE:Normal|Financial education
STYLE:Normal|Financial Q&A
STYLE:Normal|Business Mentor
STYLE:Normal|Chidi
STYLE:Normal|Responsibilities:
STYLE:Normal|Business mentoring
STYLE:Normal|Business plan generation
STYLE:Normal|Invoice assistance
STYLE:Normal|Financial projections
STYLE:Normal|Entrepreneurship learning
STYLE:Normal|Everything else exists only to support Kemi and Chidi.

STYLE:Normal|4. Engineering Principles
STYLE:Normal|Principle 1 — Conversation First
STYLE:Normal|Whenever implementing a feature ask:
STYLE:Normal|Can this be accomplished through conversation?
STYLE:Normal|If yes,
STYLE:Normal|design the conversational workflow first.
STYLE:Normal|Screens are secondary.
STYLE:Normal|
STYLE:Normal|Principle 2 — Voice First
STYLE:Normal|Voice accessibility is a core inclusion strategy.
STYLE:Normal|Never design a feature that depends exclusively on reading.
STYLE:Normal|Every major workflow should eventually support:
STYLE:Normal|Speech-to-text
STYLE:Normal|Text-to-speech
STYLE:Normal|Voice navigation
STYLE:Normal|Voice support is a project priority.
STYLE:Normal|
STYLE:Normal|Principle 3 — Offline First
STYLE:Normal|Connectivity cannot be assumed.
STYLE:Normal|Every feature must answer:
STYLE:Normal|How does this behave when offline?
STYLE:Normal|Minimum expectations:
STYLE:Normal|SQLite local storage
STYLE:Normal|Cached user data
STYLE:Normal|Queued operations
STYLE:Normal|Background synchronization
STYLE:Normal|Automatic conflict resolution where applicable
STYLE:Normal|Offline capability is a required milestone.
STYLE:Normal|
STYLE:Normal|Principle 4 — Africa First
STYLE:Normal|Optimize for real-world constraints.
STYLE:Normal|Target devices:
STYLE:Normal|Android 8+
STYLE:Normal|Low RAM devices
STYLE:Normal|Budget smartphones
STYLE:Normal|High latency
STYLE:Normal|Expensive mobile data
STYLE:Normal|Battery efficiency
STYLE:Normal|Always prefer:
STYLE:Normal|Lazy loading
STYLE:Normal|Compression
STYLE:Normal|Efficient APIs
STYLE:Normal|Small payloads
STYLE:Normal|Minimal dependencies
STYLE:Normal|
STYLE:Normal|Principle 5 — Accessibility Before Complexity
STYLE:Normal|Do not introduce complexity unless it directly benefits users.
STYLE:Normal|Simple interfaces are preferred.
STYLE:Normal|Plain language is preferred.
STYLE:Normal|Guided conversations are preferred.
STYLE:Normal|
STYLE:Normal|5. AI Safety Requirements
STYLE:Normal|Financial advice must never rely solely on LLM knowledge.
STYLE:Normal|Required pipeline:
STYLE:Normal|User
STYLE:Normal|↓
STYLE:Normal|Embedding
STYLE:Normal|↓
STYLE:Normal|Verified Knowledge Base
STYLE:Normal|↓
STYLE:Normal|Vector Search
STYLE:Normal|↓
STYLE:Normal|Retrieved Context
STYLE:Normal|↓
STYLE:Normal|Prompt Assembly
STYLE:Normal|↓
STYLE:Normal|LLM
STYLE:Normal|↓
STYLE:Normal|Cited Response
STYLE:Normal|Requirements:
STYLE:Normal|cite retrieved sources
STYLE:Normal|identify uncertainty
STYLE:Normal|never fabricate regulations
STYLE:Normal|never invent tax rules
STYLE:Normal|never invent financial laws
STYLE:Normal|If information cannot be verified,
STYLE:Normal|the assistant must explicitly say so.
STYLE:Normal|
STYLE:Normal|6. Retrieval-Augmented Generation
STYLE:Normal|The RAG architecture is mandatory.
STYLE:Normal|Priority knowledge sources include:
STYLE:Normal|Local tax laws
STYLE:Normal|Government regulations
STYLE:Normal|SME documentation
STYLE:Normal|Financial education content
STYLE:Normal|Business compliance documents
STYLE:Normal|Curated learning materials
STYLE:Normal|Large language models provide reasoning.
STYLE:Normal|Knowledge bases provide facts.
STYLE:Normal|
STYLE:Normal|7. Scope Management
STYLE:Normal|This fellowship has one MVP.
STYLE:Normal|The MVP is:
STYLE:Normal|A conversational AI financial assistant with modular financial services.
STYLE:Normal|Do NOT build independent products.
STYLE:Normal|Every new feature must strengthen either:
STYLE:Normal|Kemi
STYLE:Normal|or
STYLE:Normal|Chidi.
STYLE:Normal|If not,
STYLE:Normal|defer implementation.
STYLE:Normal|
STYLE:Normal|8. MVP Decision Filter
STYLE:Normal|Before implementing anything, answer:
STYLE:Normal|Does this improve Kemi?
STYLE:Normal|Does this improve Chidi?
STYLE:Normal|Does this improve financial literacy?
STYLE:Normal|Does this improve SME outcomes?
STYLE:Normal|Does this reduce user effort?
STYLE:Normal|Can reviewers immediately understand why this exists?
STYLE:Normal|If most answers are "No",
STYLE:Normal|postpone the feature.
STYLE:Normal|
